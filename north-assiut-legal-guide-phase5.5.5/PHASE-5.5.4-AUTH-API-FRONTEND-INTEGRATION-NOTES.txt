المرحلة 5.5.4 — ربط واجهات التسجيل والدخول والإدارة بالـ Worker Auth API

الهدف:
تحويل واجهات التسجيل والدخول وإدارة العضويات من النموذج المحلي إلى التعامل الفعلي مع Cloudflare Worker + D1.

ما تم تنفيذه:
1) إضافة عميل API محدث:
   assets/js/auth-api-client.js

2) إضافة جسر ربط الواجهة بالـAPI:
   assets/js/auth-api-bridge.js

3) ربط المسارات التالية بالـWorker:
   - تسجيل عضوية: /api/auth/register
   - فحص اسم المستخدم: /api/auth/check-username
   - تسجيل الدخول: /api/auth/login
   - بيانات الجلسة: /api/auth/me
   - تسجيل الخروج: /api/auth/logout
   - طلبات العضوية: /api/users/pending
   - قبول/رفض الطلبات: /api/users/approve و /api/users/reject
   - المستخدمون: /api/users
   - الأجهزة: /api/devices
   - سجل العمليات: /api/audit
   - Bootstrap Status/Request

4) تحديث إعدادات المنصة لإضافة رابط Worker خاص بالعضويات:
   backend.authApiUrl

5) الإبقاء على الإدارة المحلية كاحتياطي مؤقت فقط عند عدم ضبط رابط Auth API.

مهم:
هذه المرحلة تربط الواجهة بالـBackend، لكنها تتطلب نشر Worker المرحلة 5.5.3 وتطبيق schema-auth-5.5.2.sql على Cloudflare D1 وربط AUTH_DB و AUTH_PUBLIC_JWK و ALLOWED_ORIGINS.

لا يتم وضع أي مفاتيح API داخل GitHub Pages.
